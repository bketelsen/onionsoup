# Real-issue pilot: get-bb/bb, 2026-09-18

The follow-up [Terra comparison](terra-comparison-2026-09-18.md) adds all eight
real-issue runs for GPT-5.6 Terra and matched regression quality/latency metrics
for Terra, Sol, and mini, using the unchanged v3 prompt.

The first real trial found useful distinctions that the six synthetic cases missed.
The agent executes reliably, but schema-valid output is not necessarily good triage.
In particular, the mini model confused a feature request with a defect and treated
unverified reproduction as a reason to block investigation.

## Method and boundaries

Selected eight issues from the newest 30 open API entries, excluding pull requests,
before seeing agent results. This was a purposive mix of detailed bugs, feature
requests, and ambiguous reports, not a random or representative sample. Several
reports identify themselves as agent-generated and contain unusually detailed
investigations.

Saved each issue's title, body, repository, number, and `updatedAt`. No comments,
labels, linked source files, or attachments entered the agent context. Local
pre-run review notes record expectations and ambiguities; these are assistant
judgments, not labels supplied by bb's maintainers. No GitHub mutations occurred.

All runs used Copilot. First ran the unchanged `bug-readiness-v2` prompt with
`gpt-5.4-mini`, then replayed exactly the same snapshots using prompt v3. Finally
compared `gpt-5.6-sol` on three difficult cases with the same v3 prompt. Input hashes
match between runs. There was no automatic provider or model fallback.

All eight baseline runs completed in one model step (median 2.4 seconds). With v3,
mini completed seven of eight; the crash assessment repeatedly marked environment
both present and missing and exhausted its three-step limit. Sol completed all
three selected cases in one step each (5.6, 8.4, and 11.6 seconds respectively).
These are observed request latencies, not controlled performance benchmarks.

## Review findings

**Unsupported API requests need an early scope decision.** #3904 explicitly asks
for a plugin API that does not exist. Mini latched onto the rejected PATCH request
and asked for environment details. Sol correctly recognized a request for new
functionality. The presence of an HTTP error is not enough to make something a bug.

**Readiness must not require completed reproduction work.** #3892 provides observed
behavior, candidate steps, platform details, and a candid verification boundary.
Mini still demanded verified behavior after the prompt clarification. Sol accepted
the investigation path while explicitly preserving its unverified status.

**Crash investigations expose a policy boundary.** For #3863, the initial review
predicted needs-information under the old strict reproduction wording, but already
flagged that demanding a deterministic reproducer would be unhelpful. Sol treated
the observed sequence and pinned crash evidence as a usable investigation path.
That is defensible under the clarified contract; it is not proof that the shell
restart caused the crash. A maintainer should decide whether this level of evidence
is sufficient. We did not retroactively count this as an unambiguous correct answer.

**A commit is a version.** On #3849, mini originally asked for a version beyond the
commit hashes already supplied. V3 accepted the revisions, but now treats the
source-level trace as reproduction evidence. This report sits between a missing
capability request and an interoperability defect, and the sufficiency of that
trace remains a judgment call. It is deliberately not scored as a gold label.

**Grounding is necessary but insufficient.** Every accepted quote passed the exact
substring check. It could still represent the wrong field or support an unhelpful
decision. Runtime validation cannot settle feature-vs-bug or investigability.

## Changes made

- Versioned the prompt as v3: classify unsupported API requests before checking
  bug fields, accept unverified concrete candidate steps, recognize commit pins,
  and avoid asking for a deterministic reproducer already known to be unavailable.
- Clarified the existing readiness contract; tool capabilities and result schema
  did not expand.
- Added three synthetic regression cases derived from the observed failure modes:
  an unsupported API feature request, unverified candidate steps, and a commit-pinned
  parser report. These are development examples, not held-out evaluation data.

With v3, mini passed 7/9 synthetic cases. It missed the reproduction question in the
injection case and failed to produce a valid assessment for the unverified-steps
case. There were no false-ready dispositions against those synthetic labels.
Prompt clarification alone did not qualify mini for this task.

Sol passed all nine synthetic cases with v3, with zero false-ready dispositions
against those labels. The three difficult real reports and the regression results
make it the current choice for the next supervised trial. This is a comparison on
selected development cases, not a measured production accuracy advantage. It was
not run on the other five real snapshots, and no model is selected automatically
by the application: the operator still supplies `ONIONSOUP_MODEL`.

## Local artifacts and replay

Ignored directory `runs/bb-pilot-2026-09-18/` contains:

- `manifest.json`: selection, source timestamps, omitted comment counts, and pre-run review.
- `inputs/<number>.json`: immutable snapshots used by every comparison.
- `result-<number>.json` and `records/`: v2 baseline run records.
- `v3/`: mini v3 replay and nine-case regression results.
- `sol/`: stronger-model comparison and regression results.
- `summary.json` in each run group: IDs, hashes, outcomes, steps, and latency.

Replay a snapshot through the current prompt using your configured credential store:

```sh
ONIONSOUP_PROVIDER=copilot ONIONSOUP_MODEL=gpt-5.6-sol \
  npm run triage -- run runs/bb-pilot-2026-09-18/inputs/3904.json
```

Raw snapshots and run records remain local; this report preserves the findings and
links to the original issues. The current evidence supports further supervised
evaluation. It does not establish production accuracy or authorize automatic replies.
