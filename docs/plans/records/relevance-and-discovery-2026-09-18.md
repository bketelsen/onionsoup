# Status: Test relevance, discovery, events, and skills — 2026-09-18

Evidence appendix to [the evaluation plan](../evaluations.md) and delivery report
for [backlog Phases 1–2](../backlog.md). Review below is assistant development review,
not independent maintainer acceptance. Raw inputs, outputs, and snapshots remain
under ignored `runs/relevance-2026-09-18/`; the [local packet index](../../../runs/relevance-2026-09-18/index.md)
links the inspectable results.

## Method and boundaries

Code-location v3 / prompt `code-location-v7` adds per-test `direct` or `adjacent`
relevance and a separate `testSearch` status (`completed` or `unfinished`) with an
explanation. Limits and source authority remain unchanged. Versions 1 and 2 remain
readable without invented new labels; readiness and the packet envelope keep
their versions.

The first frozen synthetic trial used seven cases: the six search regressions plus
an empty-test case. Expected relevance labels were outside model context. After
reviewing three conservative label disagreements, two explicit function/keyboard
cases were frozen as a separate follow-up. No model/prompt change separated these
trials, and original expectations/results were preserved.

Four real `get-bb/bb` reports (#3337, #3558, #3892, #3886) reuse exact previous
readiness records and pinned source `3a4288bd0f34f888a5eb43f1099f7b60fe86eea4`.
The local manifest records the rubric, runtime hash, source snapshots, and expected
limitations before these runs. All live work used Copilot `gpt-5.6-terra`. Target
repository code and tests were never executed.

The three initial synthetic disagreements were an expectation problem worth
preserving: the reports described opening a picker after provider connection,
while the tests exercised a catalog helper directly. Terra explicitly identified
that gap. The two follow-ups establish that it can still use direct for explicitly
matching triggers. This is small development evidence, not proof that its
conservative classifications are always correct.

The checked-in corpus now has nine cases and rubric version 2. Its catalog
expectation is adjacent following this review, and it includes both focused cases.
That is a documented post-trial calibration; the original frozen trial remains
**4/7**, not retrospectively re-scored as 7/7. The nine-case corpus was exercised
in the two recorded trials, not as a new independent held-out evaluation.

## Limitations and next step

Every live run reported its bounded search completed; unfinished-search handling
is covered by scripted contract tests but was not observed in this live sample.
Labels and explanatory reasons remain model judgments. Exact evidence validation
cannot establish relevance, and there is no independent human acceptance score.

Event exports are deterministic inspection views of existing records, not a live
transport, durable per-step journal, queue, or resume mechanism. Capability manifests
describe the existing TypeScript functions and dependencies; they are not remote
invocation endpoints or authorization grants.

The next proposed PoC is [backlog Phase 3](../backlog.md#phase-3--prove-external-composition-implemented):
choose one external orchestrator and prove it can consume the same contracts through
a thin adapter. Remaining recommendations are retained in the backlog, including
context reconstruction, prefetch, no-progress detection, aggregate budgets,
complete execution manifests, explicit authority, durable waits, automated review,
and scoped knowledge. Model comparisons and local inference remain deferred.
