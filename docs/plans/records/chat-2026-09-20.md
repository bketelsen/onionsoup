# Evaluation record: Persistent homelab chat — 2026-09-20

Historical evidence appendix to [the evaluation plan](../evaluations.md#phase-25--persistent-chat-qualification).
This trial used scripted tests and assistant review of live artifacts. Independent
human acceptance and broad conversational accuracy remain unmeasured.

## Method and boundaries

The implementation is based on `73d18bd`, with the chat changes committed alongside
this record. The parent uses Copilot `gpt-5.6-terra`, AgentLayer and `chat-v1`;
the final domain profile is `homelab-chat-v2`. Child triage also uses Terra.
Configured NAS, container and Kubernetes collectors retain their existing fixed
read-only authority. Only normalized evidence reaches models. Credentials, private
configuration and raw runs remain outside Git.

The intended sequence was investigation, focused explanation, fresh investigation,
source refresh and brief, followed by mutation and unknown-host requests. Each
live message used a separate compiled CLI process, reopening the same session.
This tests clean restart, not recovery of an in-flight remote effect after a crash.
Bounds are twenty turns per session, eight model steps per turn and sixteen
persisted child admissions; see the [chat contract](../../specs/chat.md).

### Software qualification

`npm run verify` includes documentation, package boundaries, types, compiled CLI
tests and the full test suite, with explicit fixture, Go and TypeScript runtime
configuration and `ONIONSOUP_RELEASE_INSTALL=1` for a fresh portable release install.
It passed with 265 tests, zero failures and zero skipped tests.
The scripted checks cover exclusive writers, profile binding, clean restart,
interrupted-turn recording without replay, pre-effect reservations, persistence
failure, cancellation, malformed arguments, unknown usage, session budgets,
stale/future evidence, ambiguous targets, foreign references, fixed refresh scope,
partial coverage and source provenance. Compiled CLI checks run outside the source
working directory and exercise interactive target selection and shutdown.

These tests establish implementation invariants, not task accuracy. The live trial
used Copilot only; the Codex path was not independently exercised live here.

## Limitations and next step

The CLI is suitable for a supervised read-only pilot. Normal restart is supported;
crash recovery requires an operator to verify dead processes and remove stale
locks. Lost admission responses remain unknown and consume the reserved allowance.
There is no exactly-once recovery claim, automatic tool enrollment, service write,
generic SSH, logs or diagnosis capability. Core and profile budgets are counts and
deadlines, not a hard token or monetary quota.

The next bounded experiment is everyday use of this same chat/profile interface,
collecting examples of ambiguous questions, failed sources and unwanted factual
claims in refusals. A later UI can consume the existing turn API without acquiring
new host authority. Independent user acceptance should precede broader tools or
another orchestration layer.

## Follow-up: authentication setup — 2026-09-20

After `0270413`, the operator's `hello` failed in turn
`ea8b3792-0112-41a4-8f1a-79fe0b0d7c45` before any model step or tool call.
The default local auth file was absent; the earlier successful trial had explicitly
set `ONIONSOUP_AUTH_PATH`. The generic failure hid a local setup error. This record
preserves the original failure; its historical `modelInvoked: true` meant setup
was attempted, not that a model request ran.

The CLI now checks provider setup before spending a turn and reports fixed,
actionable missing/unreadable-auth diagnostics. An ignored local symlink to the
operator's existing auth store corrected this installation without copying secrets.
Generic runtime records distinguish initialization, request failure, step exhaustion
and missing answer submission; initialization alone no longer counts as invocation.
Provider-error usage remains unknown instead of accepting an empty aggregate as zero.

Two new live Copilot/Terra greeting attempts used the default auth path and an
isolated host configuration with no targets, avoiding interference with the active
operator session. Turn `a181db8f-57b8-44d9-9d80-34596dd57f65` completed in four steps
(5,754 input / 327 output tokens), but exposed a discovery checkpoint containing an
undefined selected-target property. The final fix omits the optional property;
the scripted profile checkpoint now validates JSON, including ambiguous selection.
Turn `456e02d8-3d7c-4439-a4f0-1f200d6f5932` then completed with successful discovery
in three steps (4,261 / 202), with no child admissions. Both greetings corrected an
initial evidence-free answer submission; conversational polish remains unqualified.

Compiled CLI regression cases verify missing and malformed auth instructions,
credential-content suppression, zero consumed turns/admissions, and interactive
recovery to session commands. These checks are separate from live task quality.
Full verification passed with 266 tests, zero failures and zero skips, using the
same configured fixture/language runtimes and fresh portable release installation.
